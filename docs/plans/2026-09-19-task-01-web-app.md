# Task 01 — Apogee continuation implementation plan

**Status:** Implementation complete locally; production verification pending
**Scope:** Task 1 only
**Assessment limit:** 2–4 hours total, including work already spent
**Working target:** 210 minutes; hard stop at 240 minutes

## Goal

Finish Apogee as a polished, date-addressable NASA Astronomy Picture of the Day archive. The final result must satisfy every required Task 1 checklist item, use one advanced option that can be proved honestly, and remain simple enough to explain in a short walkthrough.

## Chosen approach

- Next.js App Router with TypeScript.
- Server-rendered page at `/?date=YYYY-MM-DD`.
- A server-only NASA adapter and backend-for-frontend boundary.
- Runtime normalization for the upstream APOD payload.
- A fixed contact sheet of up to eight nearby dates.
- Progressive enhancement for copying a share link and optional client transitions.
- One honest advanced claim: the app uses its own backend boundary so the NASA credential never reaches the browser.

Do not claim URL-synchronized search or filter state as a second advanced option. The brief describes a debounced server-backed search with URL-encoded filters; a date query parameter alone does not satisfy that option.

## Phase 1 — Make the data boundary reliable (45 minutes)

### Step 1.1 — Capture real upstream fixtures

With the real server-side key, fetch one image day and one video or non-image day. Save sanitized JSON fixtures or document their shape without credentials. The official APOD backend changed recently, so verify the live payload before finalizing the adapter.

### Step 1.2 — Normalize the upstream payload

Create a small runtime parser that produces the internal `Plate` model described in `03-BACKEND-CONTRACT.md`.

The parser must:

- reject missing identity fields;
- support the live response shape and the documented legacy shape only where evidence requires it;
- distinguish image, video, and other media;
- sanitize URLs to `https:` or an explicitly justified `http:` fallback;
- strip HTML from fields rendered as text;
- preserve title, date, explanation, copyright, source URL, and poster URL;
- surface invalid payloads as `invalid_response`, not as an empty archive.

### Step 1.3 — Add bounded resilience

- Abort each attempt after four seconds.
- Allow no more than three total attempts.
- Keep the entire request, waits included, under twelve seconds.
- Retry transient network errors, `429`, and `5xx` responses.
- Parse `Retry-After` as seconds or an HTTP date.
- Never retry before the server's stated delay.
- If the delay exceeds the remaining budget, return a rate-limit error immediately.

### Step 1.4 — Set an honest cache policy

- Historical single dates: 24 hours.
- Current day and ranges containing it: 5 minutes.
- Document that APOD editorial metadata can change.
- Prove cache behavior in the evidence file.

### Step 1.5 — Keep one backend boundary

Prefer server components calling the server-only adapter directly. Keep `/api/plates` only if a client interaction genuinely needs JSON. If retained, validate dates, cap the inclusive range to eight items, return a stable error envelope, and never expose upstream credentials or raw upstream errors.

## Phase 2 — Compose the complete page (40 minutes)

### Step 2.1 — Reconcile the composed homepage

Retain useful current work and bring the page into this clear order:

1. compact identity bar;
2. archive/date navigator;
3. focal media and title;
4. explanation plus metadata/source actions;
5. fixed contact sheet;
6. restrained footer with data attribution.

### Step 2.2 — Implement date rules

- The URL is the source of truth.
- Missing date selects the chosen Eastern-time archive date convention.
- Invalid or future dates redirect or recover to the valid current archive date.
- Previous and next actions preserve deep links.
- Next is disabled on the current date.
- The first supported archive date never creates a reversed range.

### Step 2.3 — Handle all media deliberately

- Astronomy images use `object-fit: contain` in the focal frame.
- Video entries use a poster or a clear media placeholder plus a source action.
- Other media never masquerades as an image.
- Missing copyright reads “See source for image credit”; do not label it public domain.

### Step 2.4 — Implement explicit states

Create visually consistent loading, empty, invalid-date, rate-limit, configuration, timeout, invalid-response, and generic error states. Recovery actions must be relevant to the current state. Do not always send the user “back to today” when they are already there.

## Phase 3 — Finish interaction and visual quality (30 minutes)

### Step 3.1 — Apply the observatory catalogue direction

Use the specifications in `02-PRODUCT-AND-UI.md`:

- near-black canvas with warm archival surfaces;
- cyan for interaction and amber for observation/status information;
- restrained hairlines, square geometry, and one serif display face;
- no generic admin dashboard, glass cards, neon bloom, 3D scene, or decorative chart.

### Step 3.2 — Make the layout responsive

- Mobile: single-column focal content and two-column contact sheet.
- Tablet: balanced content and three-column contact sheet.
- Desktop: explanation/metadata at roughly 2:1 and four-column contact sheet.
- Keep all interactive targets at least 44 by 44 CSS pixels.
- Keep utility text at least 12px and body copy near 16px.

### Step 3.3 — Repair component lifecycle bugs

- Reset image loading/error state when `src` changes.
- Derive the archive strip from current props instead of copying initial props into stale state.
- Ensure keyboard focus is visible.
- Provide copy success, failure, and insecure-context fallback states.

### Step 3.4 — Keep motion measured

- Limit transitions to roughly 180–240ms.
- Animate opacity and transform only.
- Honor `prefers-reduced-motion`.
- Avoid expensive full-frame blur/filter transitions and continuous animation.

## Phase 4 — Verify the assessment, not just the build (35 minutes)

- mobile, tablet, and desktop screenshots;

- `prefers-reduced-motion` check;
- contrast check for final rendered text styles;

- direct proof that browser requests never call the credentialed APOD endpoint;
- live URL cold-load test.

Use Next.js 16 APIs correctly: prefer `preload`, `loading`, or `fetchPriority` over deprecated image `priority`, and call the error boundary's `retry()` function where available.
